# iFLYTEK 工作周报

按用户手动指定的汇报周，起草可直接粘贴到用户指定的 i讯飞周报表单的中文周报。查找表单时，优先使用用户已提供的入口或已有《周报起草规范》。默认交付草稿，由用户审定和提交。

## 核对汇报周与绩效

- 以北京时间确定汇报周。用户指定日期时以其为准。默认采用本周一至周日，周中起草时只汇总截至起草时已发生的工作。以 bot 实际日期区间、周次和字段名为准。表单中的“上周工作总结”填写所选汇报周，“下周工作计划”对应紧接的一周。
- 先查用户已授权读取的绩效档案，按有效起止日匹配。优先使用用户已有的「周报资料/绩效目标」目录，可在相关 Codex 项目中按目录名和日期定位。将用户提供的每一期目标和指标按原意保存在该目录，以 `YYYY-MM-DD_YYYY-MM-DD.md` 命名。保留当期权重及评分口径，分别存放各周期的记录。
- 汇报周跨绩效周期时按日期分段匹配。汇报周有日期缺少目标时，先提醒用户提供对应期间的绩效内容及有效期。已覆盖的日期无需重问。若只有下周计划进入新周期，照常整理本周工作和已确定的计划，在正文外提醒补充下一期目标。
- 把已核实的工作对应到适用的绩效主线，优先保留有实际进展的事项。事项只列一次。阶段指标帮助识别“初稿、评审、上架、反馈迭代、需求调研、PoC”等进度，周报中不逐项罗列目标名称、权重或评分。保留重要的临时交办事项，避免为了凑指标而编造或拔高成果。

## 收集与核实

先读紧邻汇报周的上一期已提交周报，以用户贴出的提交原文或周报 bot 中的提交记录为准。逐项核对其中的「⭐ 下周工作计划」，一行包含多个项目或动作时拆开核实。把本周已经完成的部分写入「⭐ 上周工作总结」，沿用项目名称，写明本人实际完成的动作。例如，两套方案原定一起评审，本周只评审了一套，总结就写这一套。尚无完成依据的计划跳过，改期事项按最新安排归周。

再从本周本人发出的消息、邮件、交付物和实际参加的活动查找计划外工作，与已核实的条目合并去重。若找不到上一期提交版，照常整理可核实的工作，在正文外简短注明计划核对缺口。

| 来源 | 查什么 |
| --- | --- |
| i讯飞聊天 | 查看有关项目群、伙伴对接群和私聊，核对本人承担的工作、材料版本、反馈和下一步。 |
| 微信工作聊天 | 直接查看 Mac 微信相关工作群和私聊，包括本周新出现的伙伴。沿相关会话读到起草时最新的确认、取消、改期或替代安排。 |
| i讯飞日程 | 浏览汇报周与下周的本人日程，用于发现主要分享、评审、客户拜访和接待。阅读更新过的邀请，并与相关聊天、邮件或用户说明对照。 |
| i讯飞「任务」模块 | 写下周计划时查看本人待办，核对分工、截止日期和最新状态。纳入下周到期或已明确安排下周推进的本人事项。无截止日期或已逾期的待办，按最新沟通判断是否确需下周跟进。与日程、聊天中的同一事项合并，用户明确变更的安排以最新说明为准。 |
| Mac「邮件」里的 iFLYTEK 工作账号 | 在该账号中查收件、已发送和相关归档，对照往来邮件、材料附件、会议邀请及变更。限定到公司账号，跳过个人邮箱。 |

优先用能读取相应内容的已授权连接。读取不全时尝试对应 Mac 应用；电脑使用记录或近期材料可帮助定位。只有实际读到的渠道才算已核对。若关键来源仍不可读，在可粘贴正文之外简短指出缺失范围；只有影响实质判断时才集中询问。

## 判定工作状态

- 每个总结条目先回答“我具体做了什么，有什么记录能说明是我做的？”核对发件人、原消息作者、文档贡献者或纪要中的实际分工。可采用本人给出的评审意见、发送或修订的材料、推动的协调动作、实际参会记录，以及其他参与者对本人具体贡献的明确确认。用户对本人线下工作的直接说明也可以作为依据。
- 同事之间的群聊、群公告、抄送、被 @、表情回应或一句“收到”，单独出现时均不足以列为本人工作。区分转发人和原作者、被邀请和实际参加、接到分工和已经完成。多人协作只写自己能核实的部分。例如，同事在群里完成方案，本人只收到通知，整项跳过；本人提出修改意见、同事随后定稿，可写“参与方案评审并反馈修改意见”。
- 客户或同事的消息可以更新本人事项的状态，如对方取消本人正在筹备的拜访。按最新消息修正计划，并保留本人实际完成的筹备工作。仅与绩效主线相关但找不到本人参与证据的事项，直接从草稿中剔除。
- 按“对象、事项、本人动作、日期、最新状态”区分独立工作。对同一安排优先采用用户的最新纠正、主办方的明确消息或更新邀请，并核对消息所指的会议与日期。邀请、订会议室和准备材料只能证明筹备；会后纪要、交流反馈、现场记录或本人确认可以支持写“交流”或“接待”。
- 写下周计划前，对每项已排期的拜访或会议查一次最新状态。例如日程仍有周五拜访，微信后续已确认取消，就移出计划；本周确有材料准备或接待筹备的，可以单独写本周已做的动作。明确改期则按新日期归周，待重新约定且没有具体行动的安排先不列。
- 下周优先写已约定、已分工或由用户明确指定的下一步。只写本人可归属的进展，区分团队成果、工作建议与实际安排。

## 写成可粘贴的周报

保留两个标题「⭐ 上周工作总结」和「⭐ 下周工作计划」。每项单独一行，以中文分号收尾。默认不加序号、项目符号或分类小标题。「⭐ 待协调资源」仅在有明确资源诉求或用户指定时追加。来源缺口或待确认问题放在正文之外。

总结按通用解决方案、项目与商机支持、伙伴沟通交流与接待的大致顺序排列；渠道合作与其他协同可接在相关事项后。下周安排可将已确认的重要活动提前。每行写“具体对象＋动作／阶段”，保留必要的地区、机构、语言版本和进度词。省略技术细节、例行过程和页数，除非它们就是当周交付。不同伙伴的独立交流分别列出；同一伙伴的不同产出分开列；动作和阶段相同的多个方案可以合并。

起草时参照「周报资料/周报风格参考.md」中用户手动提交的完整范例，沿用短句、项目简称和阶段词，如“来访筹备”“英文版精校”“内部评审”。每行写一件事，优先写对象和动作，只在影响事项判断时补充结果。范例用于模仿表达，事实按所选汇报周重新核实。

交付前逐条确认“本人动作、事实依据、实际阶段”都能说清，剔除旁观的群动态。复核本期绩效覆盖情况、各来源的实际可读范围、独立事项是否漏列，以及下周每个约会的最新状态。
