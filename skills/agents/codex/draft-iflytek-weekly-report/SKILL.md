# iFLYTEK 工作周报

按用户手动指定的汇报周，起草可直接粘贴到用户指定的 i讯飞周报表单的中文周报。查找表单时，优先使用用户已提供的入口或已有《周报起草规范》。默认交付草稿，由用户审定和提交。

## 核对汇报周与绩效

- 以北京时间确定汇报周。用户指定日期时以其为准。默认采用本周一至周日，周中起草时只汇总截至起草时已发生的工作。以 bot 实际日期区间、周次和字段名为准。表单中的“上周工作总结”填写所选汇报周，“下周工作计划”对应紧接的一周。
- 先查用户已授权读取的绩效档案，按有效起止日匹配。优先使用用户已有的「周报资料/绩效目标」目录，可在相关 Codex 项目中按目录名和日期定位。将用户提供的每一期目标和指标按原意保存在该目录，以 `YYYY-MM-DD_YYYY-MM-DD.md` 命名。保留当期权重及评分口径，分别存放各周期的记录。
- 汇报周跨绩效周期时按日期分段匹配。汇报周有日期缺少目标时，先提醒用户提供对应期间的绩效内容及有效期。已覆盖的日期无需重问。若只有下周计划进入新周期，照常整理本周工作和已确定的计划，在正文外提醒补充下一期目标。
- 依据当期绩效主线选取有业务进展的事项，也保留重要临时交办。目标权重和评分口径仅用于筛选。

## 逐项核对上周计划，写本周总结

读取汇报周前一周已提交的周报，以用户提供的原文或周报 bot 的提交记录为准。逐项核对其中的「下周工作计划」，一行涉及多个项目或动作时拆开判断。沿用项目名称，只把本周已完成的部分写入总结。例如，两套方案原定一起评审，本周只评审了一套，就写这一套。再从本人当周记录补齐计划外进展。

对照以下来源核实本人做了什么、做到哪一步。

- **i讯飞聊天和微信工作聊天**。分别查看项目群、伙伴群和私聊，留意本周新对接的伙伴。核对原作者、本人分工、交付或反馈，读到最近一次相关确认。
- **i讯飞日程**。查看本周和下周的会议、评审、拜访及接待。邀请、预订和材料准备可作筹备依据，实际参加可由会后纪要、现场记录、交流反馈或本人说明核实。
- **Mac「邮件」的 iFLYTEK 工作账号**。查收件、已发送及相关归档，核对材料、交付要求、邀请和变更，跳过个人邮箱。

以本人消息、交付物、具体评审意见或其他参与者对本人贡献的明确确认为依据。单凭被抄送、被 @、回复“收到”或看到同事交付，不能归为本人成果。区分初版输出、内部评审和评审后修订，局部样稿按实际完成范围写。

## 参考本人待办，写下周计划

查看 i讯飞「任务」模块的本人待办，核对分工、截止日期和状态。选入下周到期或已明确下周推进的事项。无期限或已逾期的任务，根据最新沟通判断下周是否确需跟进。

结合用户明确的安排、邮件要求、上期未结事项及本周评审或客户交流约定的后续，补齐个人交付与项目跟进。同一动作合并一次，出差与同期其他工作可并列。客户表达兴趣后，确认本人有跟进分工再列。尚未约定会议时间但已分工约访或备料，可写“推进确认客户交流和内部准备”。沟通轮次和提交节点以记录或用户确认为准。

对每个已排期事项核对最新状态。以用户最新说明、主办方确认或更新邀请为准，按具体事项处理取消或改期，同一伙伴的其他合作分别判断。本周已完成的筹备仍可写入总结。

## 交付草稿

参照「周报资料/周报风格参考.md」中的手动提交版，沿用短句和项目简称。保留「⭐ 上周工作总结」和「⭐ 下周工作计划」，每项一行，以中文分号收尾，默认不用序号、项目符号或分类小标题。有明确诉求时再加「⭐ 待协调资源」。

总结按通用方案、项目与商机支持、伙伴交流与接待大致排列，下周可将重要活动提前。每行写具体对象、本人动作及阶段，保留必要的地区、机构和语言版本。独立交流或产出分列，同阶段的多个方案可合写。服务于同一成果的整理、转发或排期可并入该项或省略，技术细节仅在本身构成重要交付时展开。

各来源优先通过已授权连接读取，读取不全时尝试相应 Mac 应用，电脑使用记录或近期材料可帮助定位。若上期提交版或关键来源仍不可读，照常整理可核实的部分，在正文外简短注明缺口。重要后续的时间或分工仍影响判断时，集中提示用户确认。

## 收到最终提交版后复盘

用户发来最终提交版时，找到同一汇报周助手最后一次实际发给用户的完整草稿，包括按用户意见优化后的版本。当前对话找不到时先查该周相关对话，仍无法定位再请用户补充。

分别对照总结和计划，逐项看增删、合并拆分、跨栏或跨周调整，以及本人动作、阶段和措辞的变化。区分起草时可避免的遗漏与提交前新增的事实。已有规则覆盖的指出执行偏差，可复用的新改进更新到周报 Skill 对应位置，具体客户事项留在当周记录。向用户简述主要差异及实际更新。
