# PPTX 定向文本改写

适用于只改文案、不重排的任务。使用 Codex/WorkBuddy 当前可用环境；不依赖 editor_sdk、present_files 或固定托管 Python 路径，也不自动安装依赖。

## 工作流程

1. 备份原件，导出和阅读目标文本。确认是否包含备注、母版/版式、表格、组合形状、图表和嵌入对象；不把只有幻灯片正文的扫描称为全量。
2. 按任务制定精确“源 → 目标”规则，按源长度降序应用。繁转简仅在用户要求时启用 OpenCC `t2s`；普通改写不强制转换，不把“数据不出境”自动改成“数据不出域”等含义不同的术语。
3. 优先在各 run 的文本节点上修改。若逐 run 变换的拼接结果不等于整段目标文本，保留整段原文并列为人工处理；绝不把整段写入第一个 run 后清空其余样式。用户接受样式变化或有可靠字符映射后才单独处理。
4. 保存为新文件，复读对照文本清单；核对跳过项、未覆盖对象、词义和事实；对混合字体、颜色、加粗及长短变化显著的页面检查换行、溢出和裁切。不得承诺“100% 保留格式”。
5. 用户明确要求改原文件时，在副本验证完成后替换原件；编辑器仍持有旧版本时先处理冲突。不要未经同意关闭其应用。

## 已提供的精确替换工具

[scripts/rewrite_pptx.py](scripts/rewrite_pptx.py) 修改选定 XML 中的文本节点，保留其 run 属性，不重建页面。需要已有 `lxml`；可选繁简功能需要已有 `opencc`。未选中或无需修改的 ZIP 部件保持原始字节内容。

```text
python <skill>/scripts/rewrite_pptx.py input.pptx output.pptx --rules rules.json --report report.json
```

`rules.json` 是 `[ ["源短语", "目标短语"], ... ]`。可加 `--t2s`、`--include-notes`、`--include-shared`（母版/版式）。工具拒绝原路径覆盖和覆盖已有输出。默认只处理幻灯片中的形状、组合和表格段落，不修改图表 XML、SmartArt 数据、图片内文字或嵌入对象；脚本结果必须结合该范围解释。报告有跨 run 跳过项时，不得宣称全量替换成功。

保持设计性空格；只在确认是本次替换造成的异常时清理。改写较长或跨语言文本即使 run 属性不变，也可能换行或溢出，必须在可用目标软件/渲染工具中检查；无法渲染时明确未验证。
