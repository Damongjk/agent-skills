# i讯飞云文档质量与协作

所有平台操作只通过当前连接的 ifeishu MCP。首次批量操作先读 `ifeishu_conventions`；收到任何资源链接先 `ifeishu_inspect`，按返回类型进入文档、表格或 Base 工具。认证由 MCP 管理，不复制 token、应用密钥或个人 ID 进技能。

## 结构与排版

- 文档名称就是标题，正文不重复同名最高标题。当前 conventions 约定章节从 H1 开始逐级；尊重用户明确层级，通常最多三级，不能把旧 H2 默认当平台限制。
- 开头交代结论/目的；按内容选短段落、列表或真实表格。表格目标是可读、可维护的原生组件，不是带竖线的伪表格。
- 当前 doc_create/update 是 Markdown 输入、固定 v1 写入；不能保证 Markdown 表格都会生成原生表格。先看实际返回并回读；结构需要视觉确认时检查成品。工具无法满足时说明缺口，使用清晰列表或提供待维护方案，不绕过 MCP 直连 API，也不把“输出成功”当排版正确。
- 对比分析可读 [对比结构参考](references/comparison-analysis-patterns.md)，其中排版目标服从当前工具能力与验证结果。

## 创建与修改

新建仅在用户要新文档时执行，默认使用 MCP 内置的 From My Agent 目录；指定目录或 Wiki 空间时使用已确认坐标，不把正文文档 token 当文件夹 token。

每轮更新前 `ifeishu_doc_read` 取得最新内容，保护用户手改。优先 append/insert_before/insert_after/replace_range；按标题定位要用真实、可消歧标题，不猜标题级别或把同名章节混淆。工具会校验标题，但仍须对照最新内容。overwrite 仅在任务明确需要、范围清楚时使用，不因局部更新失败就全文覆盖。

写入后回读受影响内容，核对目标章节和未改区域。若失败且可能已送达，先读现状再决定重试；不要重复追加或创建。多轮迭代维护同一终稿链接；备选稿与过程材料可留在本地，避免每轮新建云文档。

## 交付、定位与权限

新建后在当前对话返回工具给出的真实链接；更新后简要说明实际变更。额外 IM/邮件通知需要用户明确授权，不依赖已退役的 Hermes Gateway。

搜索空结果不等于不存在或无权限。优先已知链接 + inspect；不能因列表没出现就新建副本。仅按报错提示区分身份、scope、资源共享和平台限制，不自动公开分享或扩大权限。资源索引留在本机业务上下文或用户认可的位置，不写回本技能的 Git 包。

云空间 `.md` 普通文件与 Docx 云文档是不同对象。历史平台限制是 `.md` 内容 patch/overwrite 不可用；不能照搬公有云能力，也不能用“删后重建”默认绕过用户的原件。Base 附件、Wiki 和平台排障按 `ifeishu-mcp-ops` 的参考处理。
