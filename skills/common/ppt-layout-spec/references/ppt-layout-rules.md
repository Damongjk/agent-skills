# PPT 排版操作框架 · 规则集（Rule Set）

> 本文件是 `ppt-layout-spec` 技能的唯一规则来源（single source of truth）。  
> 每条习惯统一格式：**规则 + 为什么（第一性原理）+ 反例/正例 + 适用场景 + 检查勾选**。  
> 维度：版式与栅格(L) / 字体与层级(T) / 配色与对比(Co) / 图文与图表(V) / 信息密度与叙事(D) / 叙事与结构(N) / 一致性(C) / 动画与交付(M)。

---

## 设计前速查（Design-Time Pre-flight）

> **用途**：**动笔前**先过一遍这张清单，把每条规则转成当前页的"建造约束"，从第一稿就满足规范，而非事后返工。细节与理由见下方各规则条目（本文件即唯一权威来源）。
> **用法**：设计某页时，只对该页会用到的元素类型逐条确认；审计既有页时，逐条打 PASS / FAIL / MANUAL。

- **L1** 对齐类文本框四边内边距归零。
- **L2** 短文本（标题/KPI/标签/页码）关自动换行；尺寸模式="根据文字"；正文开换行。
- **L3** 页眉/页脚/页码走版式占位符，不自绘等价框。
- **L4** 组内间距 < 组间间距；元素不贴边、四周留安全边距。
- **T1** 在版式约束内最大化字号；全篇字号梯度统一、同级同字号。
- **T2** 对外默认英文单语；双语/纯中文仅在明确指定时用。
- **T3** 全篇字体族 ≤2 种（标题一种、正文一种）。
- **Co1** 主色 ≤3；单页强调色仅一处，其余弱化为灰。
- **Co2** 文字与背景高对比（正文 ≥4.5:1，大字 ≥3:1）。
- **Co3** 色彩语义全篇一致（同一含义同色；涨跌/正负色义统一）。
- **V1** 形状内嵌文字，不拆成"色块 + 文本框"两个元素。
- **V2** 圆角矩形统一 adj=0.08（恒定占比）；药丸/圆形除外。
- **V3** 图表标题写结论句；图内只强调一个数据点。
- **V4** 去图表垃圾：无 3D、无冗余网格线、不粘 Excel 截图。
- **V5** 图标用矢量图片/形状，禁用字符图标与 emoji。
- **D1** 主区域内无大面积空白、无无内容色块。
- **D2** 内容区延伸至页脚安全线，页脚之上不留 >1cm 空带。
- **D3** 全页装饰 ≤2 处；强调手法仅一处。
- **N1** 标题写成完整结论句（含动词/数据），非主题词。
- **N2** 每页只讲一个观点；标题含"且/和/与"→ 考虑拆页。
- **N3** 抽读全篇标题，应串成一条连贯故事线。
- **C1** 全篇套用统一参考线/栅格。
- **C2** 参考页只取视觉语言，不照抄其字号/留白等保守参数。
- **C3** 复杂结构页（架构/流程/拓扑）保留构图仅美化；普通内容页可按内容重排。
- **C4** 阴影/描边/渐变/图标风格全篇统一（与 V2 配套）。
- **C5** 沿用模板只取母版元素 + 配色 + 风格；新建页版式按内容设计。
- **M1** 重排指定页默认输出独立文件 + 成品渲染图；用户指定完整 Deck 或原位修改时遵循其要求，并先备份。
- **M2** 仅排版优化任务不擅自创作文案：输出文字 ⊆ 原页文字 ∪ 用户原话。**排版优化类任务默认不改原文案**，仅当文案确犯某规则（如 N1/N2）时逐条提出、经确认才改。

## 版式与栅格（Layout & Grid）

### L1 文本框默认去除四边内边距

- **规则**：对齐类文本框四边内边距（上/下/左/右）设为 0；装饰性卡片、引文块保留有意的容器留白。0.1 英寸 = 91440 EMU；四边默认值需读取实际 XML，不假设全部相同。
- **为什么**：PPT 文本框默认带约 0.1″ 内边距。多个框边缘对齐时，文字因内边距向内缩进，出现"框对齐、字没对齐"的视觉错位。去边距后，框边界 = 文字边界，对齐才真实。
- **反例**：两个并排标题框左缘对齐，但各带左边距，肉眼看文字左缘不齐。
- **正例**：边距归零，框左缘即文字左缘，多框严格对齐。
- **适用场景**：标题、正文、标签类文本框；刻意缩进的引文块可保留内边距。
- **检查勾选**：☐ 文本框内边距已归零？

### L2 尺寸模式选"根据文字" + 显式管理自动换行

- **规则**：文本框尺寸模式设为"根据文字调整形状大小"（Resize shape to fit text）；并按内容类型管理"自动换行"开关——单行元素（标题、KPI、标签、页码）关闭换行，多行正文开启换行。
- **为什么**："根据文字"让框跟随内容，避免留白或裁切。单行标题若开换行，在字体替换/分辨率/缩放不同的设备上可能被强行折行，破坏版式。
- **反例**：单行主标题开了换行，客户机上因字体缺失被折成两行，标题区塌陷。
- **正例**：标题关换行 + 根据文字 → 跨设备稳定单行；正文开换行 → 长文本自动回流。
- **适用场景**：标题/KPI/标签/页眉页脚等短文本关换行；段落正文开换行。
- **检查勾选**：☐ 单行元素已关自动换行？☐ 尺寸模式为"根据文字调整形状大小"？

### L3 套模板时优先复用版式占位符，不自绘等价元素

- **规则**：套用既有母版/版式时，页眉（章节行+标题+英文副题）、页脚、页码等模板已定义的元素，一律使用版式占位符（placeholder）填入内容；不要用独立文本框"复刻"一份等价元素。
- **为什么**：占位符继承母版的字体、位置与联动（换模板自动跟随）；自绘文本框脱离模板体系，换母版即错位，且与占位符元素并存时产生双份页眉页脚。
- **反例**：重建页时自绘页眉文本框+自绘页码框，套到别的模板上页眉重叠或缺失。
- **正例**：直接对 `文本占位符`（title/subtitle/footer placeholder）写文字，位置字体全由版式控制。
- **适用场景**：一切"基于现有模板新建/重排页"的任务。
- **检查勾选**：☐ 页眉/页脚/页码是否走占位符？☐ 是否存在与占位符功能重复的自绘框？

### L4 元素间距体现亲密性，四周留安全边距

- **规则**：相关元素之间的间距，应小于它们与不相关元素之间的间距（亲密性原则），让"分组"由间距本身表达，而非依赖边框或底色；同时任何元素都应避开幻灯片边缘与容器边界，保留安全边距（元素不贴边，形状内文字不与边框相碰）。
- **为什么（第一性原理）**：人眼靠"距离"判断"关系"。间距等距铺开时，观众无法判断谁和谁是一组，只能逐字阅读去反推结构；用间距分组，分组关系一秒可见。元素贴边则带来"拥挤、未完成"的廉价感，且投影裁切/打印时会丢失内容。
- **反例**：四个卡片等距铺满，卡片标题与正文的间距 = 卡片与卡片之间的间距，读不出归属；文本框紧贴页面左缘，投影裁切后首字被切。
- **正例**：同一卡内标题—正文间距 0.3cm，卡与卡间距 0.8cm，分组一目了然；整页内容四周留出 ≥1cm 安全边距。
- **适用场景**：所有含多组元素的页面。C1 定义统一页边距后，本规则负责组内/组间的间距关系。
- **检查勾选**：☐ 相关内容间距是否小于非相关内容间距？☐ 元素是否均未贴边、保留安全边距？☐ 装饰性卡片内文字是否留有内边距（与 L1 对齐类文本框归零相区分）？

## 字体与层级（Typography & Hierarchy）

### T1 约束内最大化字号，保证可见性（Visibility First）

- **规则**：在"不破坏版式"（不溢出/裁切、不产生破坏版式的折行、不破坏信息密度与结构）且"全页（全篇）层级统一"（标题/正文/注释的字号梯度保持一致，同级文字跨页同字号）的前提下，尽可能增大各级文字的字号，使整体文字更加可见。
- **为什么（第一性原理）**：PPT 的本质是"被看见"：观众通常隔屏观看（投影、会议室、直播裁切），小字阅读成本极高，看不清时内容等于不存在。字号由两个边界决定：下限是可读性，上限是版式约束（容器尺寸、页面容量、层级关系）。两者之间有空间时，字号应逼近上限，而不是停在"刚好放下"的下限。常见本末倒置：为塞下内容而缩小字号，页面看似"完整"，观众却一个字都读不到。
- **反例**：为把内容塞进一页，正文压到 10–12pt，投影后不可读；或只放大标题、正文依旧小，层级差大但整体可见性仍低。
- **正例**：先锁定全篇字号梯度（如标题 28–32 / 小标题 20–24 / 正文 14–18 / 注释 11–12），再逐页把每一级推到版式约束允许的最大值；内容放不下时先删减内容、拆页或图形化，而不是整体缩字。
- **适用场景**：所有文字页面。容量不足时优先级为"删内容 / 拆页 / 图形化"，而非"缩字号"。信息密集的特殊页（附录、明细表、条款页）可下调下限，但须守住可读底线与层级统一。
- **检查勾选**：☐ 字号是否已在版式约束内最大化？☐ 全篇字号梯度是否统一、同级是否同字号？☐ 内容放不下时是否选择删减/拆页而非缩字号？

### T2 语言策略：对外默认英文单语；中文/双语仅在明确指定时使用

- **规则**：对外（含涉外/发布会）页面**不默认双语**。语言按设计需要择定，通常使用**单一语言**；除用户明确指定"中文"或"双语"外，**默认使用英文**。仅在用户明确要求双语时使用中英双语——主级标题"中文+英文"（同行优先，宽度不足时英文换到第二行；中文略大、英文略小，均加粗），底部要点卡标题"中文一行+英文一行"均加粗；独立成行的英文副题/标签按可读正文对待 ≥12pt，同行英文 ≥10pt。纯内部材料默认中文。
- **为什么**：双语不是"更专业"的默认项。语言目标不明时堆砌中英，会让标题变成"两句话抢一个位置"，稀释张力、增加阅读噪音。英文是涉外/海外场景的通用工作语言，作为默认最稳妥；是否使用双语，应由设计目标（受众、场合、模板既有语言系统）决定，而非机械铺双行。
- **反例**：未指定语言时，每页标题默认写成"中文 + 英文"两行；或英文做成 6.75–8.25pt 灰色微标签，投影不可读。
- **正例**：未特别指定时，对外页标题用英文单语（如 "Ride Hailing"）；用户要求双语时，`知识智能体 Knowledge Agent`（14/12pt 同粗）。
- **适用场景**：所有对外/涉外/发布会页面。默认英文单语；双语与纯中文均为按需选项；纯内部材料默认中文。
- **检查勾选**：☐ 未指定语言时是否默认英文单语（而非默认堆砌双语）？☐ 双语是否仅在被明确要求时使用？☐ 双语时同行英文是否 ≥10pt、独立英文行是否 ≥12pt 且与中文同级加粗？

### T3 全篇字体不超过两种（标题一种 + 正文一种）

- **规则**：整套 PPT 的字体族数量控制在 2 种以内——一种用于标题/强调，一种用于正文（若标题与正文同族，用不同字重区分层级）。不得逐页混入第三、第四种字体（含图表标签、页脚、注释）。
- **为什么**：字体是"视觉嗓音"。多种字体混用等于多人同时讲话，页面杂乱且削弱整体感；两种（一标题、一正文）足以建立层级，跨页一致性最强。咨询级规范（麦肯锡：Arial 正文 / Georgia 标题）即两字体制。
- **反例**：标题黑体、正文宋体、图表标签圆体、注释微软雅黑——四种字体同页出现。
- **正例**：全篇标题统一"苹方 Medium"、正文统一"苹方 Regular"，仅以字号与字重区分层级。
- **适用场景**：整套 Deck。品牌模板已规定字体时，以模板为硬约束。
- **检查勾选**：☐ 全篇字体族数量是否 ≤2？☐ 是否存在偶发混入的第三种字体（含图表标签、页脚、注释）？

## 配色与对比（Color & Contrast）

### Co1 配色收敛：主色 ≤3 种，单页强调色仅一处

- **规则**：整套配色以"主色 + 中性色（黑/灰/白）+ 1 个强调色"为骨架；一页之内用于"强调"的强调色仅一处，其余同色系降为背景或弱化灰。避免大面积彩虹配色或超过 3 种高饱和主色。
- **为什么**：颜色是"注意力的聚光灯"。颜色越多，聚光灯越乱，关键数据越不显眼；收敛后，唯一的高饱和色天然成为视觉锚点，观众视线自动落点。麦肯锡式"标题+数据"双锚点同样依赖配色克制。
- **反例**：一页用蓝、橙、绿、红四种高饱和色各标一部分数据，观众不知该看哪里。
- **正例**：关键数字用品牌强调色，其余数据一律 50% 灰；同一页只有一处彩色焦点。
- **适用场景**：所有内容页/数据页。主题封面、插图页可放宽。
- **检查勾选（程序化）**：☐ 高饱和主色是否 ≤3？☐ 单页强调色是否仅一处？☐ 次要信息是否已弱化为灰？

### Co2 文字与背景保持充分对比

- **规则**：所有正文与标题的字色与其背景保持高对比（浅底深字 / 深底浅字），确保投影、暗光会议室、打印三种条件下均可读；禁止浅灰字配浅底、深底配深色字。
- **为什么**：对比不足是"投影看不见"的头号原因，也是可访问性（低视力/色觉障碍）的硬要求。装饰性低对比（如浅灰小字）在屏幕上勉强可辨，投到会议室墙上即消失。
- **反例**：浅灰（#BBBBBB）小字放在白色背景；深蓝字直接压在深色照片上且无遮罩。
- **正例**：正文 #333 压在 #FFF 上；图片上的文字先加半透明深色遮罩、再用白色文字。
- **适用场景**：所有文字；叠图文字尤其注意。
- **检查勾选（程序化）**：☐ 文字与背景对比是否充足（正文≥4.5:1，大字≥3:1）？☐ 叠图文字是否有遮罩保障可读？

### Co3 色彩语义全篇一致

- **规则**：同一含义在全篇使用同一颜色（本方方案、竞品、正向指标、负向指标、风险项等各固定一色）；同一颜色不得在不同页表达相互冲突的含义。数据涨跌/正负的色义须全篇统一（涨红跌绿 或 涨绿跌红，选定一种后全篇一致，不可混用）。
- **为什么**：颜色一旦被赋予含义，观众会自动跨页记忆。若第 5 页绿色=正向、第 50 页绿色=竞品，观众会误读结论；色义漂移直接损害可信度。
- **反例**：第 5 页绿色表示"增长"、第 12 页绿色却表示"竞争对手"。
- **正例**：全篇"本方案"统一蓝色、"竞品"统一灰色、"风险项"统一红色。
- **适用场景**：整套 Deck；图表、图例、标签之间尤其需要对齐。
- **检查勾选（程序化）**：☐ 同一含义是否全篇同色？☐ 同一颜色是否有跨页冲突含义？☐ 涨跌/正负色义是否全篇统一（未混用红绿惯例）？

## 一致性（Consistency）

### C1 同一套 PPT 套用统一参考线规范

- **规则**：整套 PPT 建立并复用统一的参考线（guides）/栅格，所有页面共用，保证内容范围与视觉边界一致。
- **为什么**：无统一参考线时各页边距靠肉眼估，跨页后左右边界、标题起点漂移，整体显业余、不连贯。
- **反例**：第 3 页内容区比第 1 页窄 20px，翻页时内容"跳动"。
- **正例**：固定左边距线 + 内容右边界线，每页元素吸附同一基准。
- **适用场景**：整套提案/汇报；母版级设定一次，全篇复用。
- **检查勾选**：☐ 是否套用统一参考线？☐ 跨页内容边界是否一致？

### C2 参考页只取视觉语言，不继承其保守参数（视觉尺度校准）

- **规则**：以既有页面为风格参考时，提取的是**配色、渐变、阴影、卡片结构、双语版式**等视觉语言；字号、容器高度、留白尺度必须按 T1（约束内最大化）与 D1（铺满主区）重新校准，不得照抄参考页的数值。
- **为什么**：参考页自身可能偏保守（小字、矮容器、页底留空）。若"忠实复刻"参考页参数，等于把参考页的缺点一并继承。风格一致 ≠ 参数一致；尺度问题由规则裁定，不由参考页裁定。
- **反例**：参考页卡片标题 10.5pt、页底留 2cm 空带，重排版原样照搬，成品"像但小气"。
- **正例**：沿用参考页的蓝青渐变与阴影卡片，但卡片标题升到 14pt、正文 10pt、内容区下缘推到页脚安全线。
- **适用场景**：一切"参照某页风格重排/新建页"的任务。
- **检查勾选**：☐ 是否只继承了视觉语言而未继承字号/留白等保守参数？☐ 成品尺度是否通过 T1/D1 复核？

### C3 按内容复杂度决定构图保真：复杂结构页保留构图，普通内容页可重排

- **规则**：优化既有页排版时，按该页内容的**结构复杂度**分流：
  - **复杂结构型内容**——系统架构图、复杂流程图、组件关系/拓扑图、多层级逻辑图等——**保留其原有构图语法**（元素的相对位置、连接关系、分组与层级、堆叠次序），**只做视觉美化**（配色、字体、间距、圆角、样式统一），**不整体重排/重构**。
  - **普通内容**——简单对比（A vs B）、几个内容块的陈列、要点卡片、图文说明等——**允许按内容重新设计版面**（视觉语言仍沿用原稿）。
- **为什么（第一性原理）**：复杂结构图的版面本身承载语义——框的位置表示层级、连线走向表示数据/控制流、相邻关系表示归属。重排它等于重画逻辑，极易在"更好看"的同时把关系画错；且这类图信息量大、约束多、"更好看"的改造空间小，重构质量难以稳定达标。普通内容相反：版式不承载语义，重排能显著提升清晰度与美观度、风险低。**判据是"内容的结构复杂度"，不是"单页 vs 整份"。**
- **反例**：把一张系统架构图"重新设计"成分栏卡片，丢了层级与连线语义；或把两个简单要点硬套原构图，浪费空间又不好看。
- **正例**：架构图保留原框位与连线，仅统一配色/字体/圆角与间距；而"方案 A vs 方案 B"这类简单对比，重排成左右双栏对照，更清晰。
- **适用场景**：**优化既有页排版**时的逐页判据。复杂结构页 → 保留构图、仅美化；普通内容页 → 允许重排版面。新建页（按模板风格）见 C5。
- **检查勾选**：☐ 该页是否属于复杂结构型（架构/流程/拓扑）？若是，构图语法是否原样保留、仅做美化（未重构）？☐ 若为普通内容，重排是否确实提升了清晰度（而非为改而改）？

### C4 风格元素全篇统一（阴影/描边/渐变/图标风格）

- **规则**：整套 PPT 的视觉风格元素保持一致——阴影（有/无、方向、模糊度）、描边（有无、粗细、颜色）、渐变（是否使用及方向）、图标（线性/填充、圆角/直角、粗细）、图片处理（圆角/直角、滤镜）等，全篇采用同一套参数。
- **为什么**：风格元素是"品牌指纹"。同一份 Deck 里有的卡片带投影、有的没有，有的线性图标、有的填充图标，会读作"多人拼接"；即便单页都不丑，整体仍显廉价。统一后，观众注意力才能只落在内容上。
- **反例**：第 3 页卡片带柔和投影，第 7 页卡片扁平无投影；图标一半线性一半填充。
- **正例**：全篇卡片统一 8% 圆角 + 同一组阴影参数；图标统一白色线性样式。
- **适用场景**：整套 Deck；与 V2（圆角统一）配套，共同构成"风格一致性"检查。
- **检查勾选**：☐ 阴影风格是否全篇一致？☐ 描边/渐变是否一致？☐ 图标风格是否统一？☐ 是否与 V2 圆角参数配套统一？

### C5 沿用模板/参考 PPT 时，继承母版体系而非其页面版式

- **规则**：当用户提供一套模板或参考 PPT 供"沿用"时，继承其**母版基本元素（版式占位符体系、页眉页脚/页码、主题色板、字体系统）、配色与整体风格**；**不继承其具体页面的版式（layout）**——每一页的版面应根据该页内容重新匹配与设计。**典型场景：按某模板风格新建页面。**
- **为什么**：模板/参考稿的价值在"视觉体系"（可复用的风格资产），而非"每页长什么样"。原页面版式是其自身内容的产物；直接搬用等于逼新内容去适配旧版式，导致文字被裁、留白失衡或信息塞不进。"用它的风格，排我的内容"才是正解。
- **反例**：按参考 PPT 风格新建页时，把原第 5 页的三栏版式原样套到内容完全不同的一页上，导致溢出或大片留白。
- **正例**：继承其色板、字体、页眉页脚与占位符规则；但按本页内容重新选择"图文左右 / 上图下文 / 卡片宫格"等版式，并沿用其视觉语言（渐变/阴影/圆角/图标风格）。
- **适用场景**：一切"沿用某模板/参考 PPT"的任务，尤其是**按模板风格新建页面**。**与 C3 的分工**：C3 管"**复杂结构型内容页**在优化时保留构图"；本规则管"**继承体系、按内容设计版式**"。两者按内容复杂度各管一类，不冲突。
- **检查勾选**：☐ 是否继承了母版元素/配色/风格（而非抛弃）？☐ 是否未照搬原页面版式、而是按内容重新匹配？☐ 新建页是否沿用模板风格而非自造风格？

## 图文与图表（Visuals & Charts）

### V1 形状内嵌文字，避免色块与文字分离

- **规则**：带文字的形状（按钮、标签、流程节点、数据卡、图标+说明）直接在形状内写入文字，不要把"色块"和"文字"拆成两个独立元素。
- **为什么**：拆分后二者各自独立，移动/改色/对齐都要同步两次，极易错位遗漏；也无法作为整体统一复制、栅格对齐。内嵌文字随形状一起移动、缩放、改样式。
- **反例**：圆角矩形做按钮，文字是叠在上面的独立文本框；改按钮位置时文字留在原处。
- **正例**：用形状"编辑文字"直接输入，文字成为形状一部分。
- **适用场景**：按钮、标签、流程框、数据卡、图标+说明等所有"形状承载文字"的场景。
- **检查勾选**：☐ 形状与文字是否合为一体（非拆分元素）？

### V2 圆角矩形：圆度适中且全篇视觉统一（恒定占比）

- **规则**：圆角矩形（rounded rectangle）的圆度（corner radius）要适中——不过大以致挤压文字显示区、降低空间利用率。全篇统一采用**恒定圆度占比**（推荐短边的 8%，即 python-pptx 归一化 `adjustments[0] = 0.08`，OOXML `<a:gd>` 中为 `val 8000`），而非固定绝对磅值。
- **为什么（第一性原理 + OOXML 真相）**：①圆度过大时四角圆弧侵占内容区，标题/文字在边角处被"吃掉"或显得拥挤，也浪费可用面积。②关键：python-pptx 的归一化圆角参数与 OOXML 整数相差 100000 倍；对 roundRect，圆角半径按归一化比例与形状短边计算。因此**只要 adj 恒定，圆角半径就自动随形状尺寸等比缩放**——大卡片半径大、小标签半径小，视觉"圆润感"天然统一。反之，若按 PowerPoint「按磅设绝对半径」那种固定磅值（如 8pt），大卡片会显得方硬、小标签却过圆，反而分裂。所以"恒定 adj"才是正确且最稳健的做法（缩放/改尺寸不变形）。
- **反例**：全篇固定 8pt 绝对圆角；大号数据卡近乎直角、小号标签却很圆，视觉语言分裂。或圆度开到 20%+ 导致标题在边角被切。
- **正例**：所有 roundRect 的 adj 统一设为 0.08（短边 8%）；药丸/圆形等刻意设计可保留大 adj（>0.45）不强制。
- **适用场景**：所有圆角矩形（按钮、标签、数据卡、容器框）。故意做"药丸"（pill）/圆形等特殊设计除外（adj 明显偏大，规则应跳过）。
- **检查勾选（程序化）**：☐ 圆角是否未过大（adj ≤ 0.2 不影响文字）？☐ 非刻意圆角元素的 adj 是否统一为 0.08（恒定占比）？☐ 药丸/圆形（adj>0.45）是否已排除？

### V3 图表标题写结论，数据只强调一个焦点

- **规则**：每张图表的标题写成一句完整结论（如"华东贡献六成销售额，但增速最慢"），而非主题词（如"各地区销售额"）；图表内只用一个颜色/标注强调唯一关键数据点，其余数据统一弱化（灰）。
- **为什么（第一性原理，源自 Zelazny《用图表说话》）**：观众看图只有几秒，没有时间自己找结论。标题写主题，观众要自行推导结论，多半推不出或推错；标题写结论，图才成为"证据"。单一焦点同理——多处强调等于没有强调。
- **反例**：标题"月度销售趋势"，图内红黄蓝绿四条线全部高亮。
- **正例**：标题"销售额连续五个月下滑，三月起跌幅扩大"，仅下滑起始点标红并加数据标签。
- **适用场景**：所有数据页。探索性/自用草稿图可不受此限（此时尚无结论）。
- **检查勾选（程序化）**：☐ 图表标题是否为一句完整结论（含判断/数据）？☐ 是否仅一个数据点被强调、其余弱化？

### V4 去除图表垃圾（Chart Junk）

- **规则**：删除一切不传递信息的图表元素——3D 效果、冗余网格线、背景填充、装饰性渐变、多余图例、无谓数据标签；禁止直接把 Excel 截图/默认图表样式粘进页面，应重建为符合页面风格的矢量图表。
- **为什么（源自 Tufte 数据墨水比）**：每一份"不代表数据"的墨水都在稀释"代表数据"的墨水。3D 还会歪曲比例、误导判断；Excel 截图则同时带来风格割裂与"未做决策"的信号。
- **反例**：3D 饼图 + 深色背景 + 粗网格线；或直接粘贴一张带默认蓝、带边框的 Excel 折线图截图。
- **正例**：白底、无网格线、仅保留必要轴标签与数据标签的扁平柱状/折线图，配色与页面一致。
- **适用场景**：所有含图表的页面。
- **检查勾选（程序化）**：☐ 是否无 3D 图表类型？☐ 是否已去除冗余网格线/背景/装饰渐变？☐ 图例/数据标签是否仅保留必要项？☐ 是否未直接粘贴 Excel 截图（而是重建图表）？

### V5 图标使用矢量图片/形状，禁用字符图标与 emoji

- **规则**：需要图标时，使用矢量图标资源（SVG/PNG 图标图片，或由形状组合绘制的图标），不要用"字符图标"——即用 Wingdings/Webdings 等符号字体字形、emoji、或直接键入 ▲ ● ★ ▶ ✔ 等符号来充当图标。
- **为什么（第一性原理）**：字符图标本质是"文字"，其宽度、字形与基线由字体决定——换台电脑字体替换后会变形、宽窄不一或直接显示为方框；作为文字也无法像图形对象那样独立对齐、缩放、改色、统一尺寸，导致多图标视觉重量参差、整套难以对齐（与 L4/C4 冲突）。矢量图片/形状图标是"图形对象"，尺寸、位置、颜色可精确控制，跨设备稳定。
- **反例**：用 emoji 🚀 或 Wingdings 字符做流程图标；用 ▲/●/★ 字符做要点符；协作方换电脑后图标错位、串行或变方框。
- **正例**：从图标库取 SVG 导出为形状/图片插入，统一尺寸与配色；或以形状组合绘制线性图标。
- **适用场景**：所有需要图标元素的页面（流程节点、要点符号、卡片角标、导航图标）。
- **检查勾选（程序化）**：☐ 是否存在用字符/emoji 充当图标（应替换为矢量图片/形状图标）？☐ 图标尺寸/颜色/风格是否统一（配合 C4）？☐ 换字体/跨设备后图标是否稳定不变形？

## 信息密度与叙事（Density & Narrative）

### D1 主区域避免大面积空白与无内容色块，内容合理分布

- **规则**：页面主展示区内，除非为刻意设计（如章节分隔页、金句页），否则避免出现"大部分为无实际内容的空白"，也不要放置没有承载内容的装饰性色块；有效内容应在主区域内合理分布、填满可用空间。
- **为什么**：①大面积留白且无内容，显得信息密度低、准备粗糙，浪费一页的展示机会。②空色块只增加视觉噪音却不传递信息，反而干扰重点。③内容合理分布能让观众视线有落点、节奏均衡，专业感更强。
- **反例**：一页只左上角放两行字，其余约 80% 空白；或角落放一个纯色矩形块却无文字/数据。
- **正例**：内容按栅格铺满主区域，留白只存在于元素之间的合理间隔；若内容确实少，用"一页一观点"+放大字号/图形化来撑满，而非留空。
- **适用场景**：内容页、数据页、对比页；章节分隔/金句等"留白即设计"的页面除外。
- **检查勾选**：☐ 主区域是否无大面积无内容空白？☐ 是否无无内容的装饰性色块？☐ 有效内容是否在主区域合理分布？

### D2 内容区须延伸至页脚安全线（页面饱满度）

- **规则**：内容页的主体区（列/带/卡组）下缘应推进到页脚安全线附近（约 17.5–17.75cm @ 33.87×19.05 页面），页脚行（logo/页码）之上不留超过 ~1cm 的无内容空带；底部要点卡等元素高度随之撑足。
- **为什么**：投影画面上，页底空带会被读作"这页没做完"。饱满度是发布会级页面与草稿级页面的直接分野；内容区的纵向延伸也决定了正文能拿到的字号上限（与 T1 联动）。
- **反例**：内容在 16.1cm 收住，页脚之上留 1.5cm+ 空白带；底部要点卡只有 2.45cm 高、标题条细窄。
- **正例**：内容列 2.94→14.33cm，底部要点卡 3.06cm 高、渐变标题条 1.62cm 高（双行中英），页脚紧贴 16.9cm 以下。
- **适用场景**：所有内容页、架构页。章节页/金句页除外。
- **检查勾选**：☐ 主体区下缘是否接近页脚安全线？☐ 页脚之上是否无 >1cm 空带？☐ 底部元素高度是否撑足？

### D3 装饰预算（Decoration Budget）

- **规则**：内容页每个纯装饰元素（色带、引号、细条、徽章、结论带等）添加前必须回答"它承载什么信息"；答不出就不加。全页装饰 ≤2 处；**全页强调手法仅限一处**（同一页不同元素各自强调 = 页面内互相竞争）。
- **为什么**：主角信息密度高时（如四张产品截图），每加一处装饰都在稀释主角注意力；多处强调互相竞争后反而没有重点。参照风格时尤其易"把风格元素当必选项逐个复刻"，导致装饰堆叠。
- **反例**：一页内同时出现金句底带+引号装饰+卡片顶部细条+骑缝徽章+末环药丸+自创页底结论带（六处装饰/三处强调），用户拿到手只能逐个删除。
- **正例**：装饰仅保留必要的图片/文字分隔细线；金句以裸排大字呈现（字本身就是设计）；页面强调只有关键词蓝色一处。
- **适用场景**：所有内容页；金句页/章节页以留白为设计语言的除外。
- **检查勾选**：☐ 每个装饰元素能否说出承载的信息？☐ 全页装饰是否 ≤2 处？☐ 强调手法是否仅一处？

## 叙事与结构（Narrative & Structure）

> 本维度（N）审视页面的"逻辑与论证结构"——标题是否结论、是否一页一观点、整篇故事线是否读得通；与 D（信息密度）关注的"留白/饱和度"互补。N 检查的是"逻辑读不读得懂"，而非"好不好看"。

### N1 标题写结论，不写主题（Action Title）

- **规则**：页面标题用一句完整、可判断真假的结论句（含动词/数据），而非名词性主题词。整个 Deck 的标题应能连成一条论证主线。
- **为什么（Minto 金字塔原理 / MBB 行动标题 / Alley 断言—证据）**：忙碌的决策者只看标题。标题若只写主题（"市场分析"），读者必须读正文才知道结论；标题写结论（"德国市场年增 12%，为美国三倍"），只看标题即可理解论证。这是咨询级 Deck 与普通 Deck 的分水岭。
- **反例**："市场概况""竞争分析""财务预测"。
- **正例**："德国市场年增 12%——为美国的 3 倍""收购可产生 15% 的内部收益率"。
- **适用场景**：所有内容页标题（章节分隔页除外）。标题控制在 15 词/两行内，使用主动语态。
- **检查勾选（程序化）**：☐ 标题是否为完整结论句（含动词/数据）而非主题词？☐ 是否 ≤2 行、主动语态？

### N2 一页一观点

- **规则**：每页只传达一个核心观点（即标题）；页内所有文字、图表、图形都只作为该观点的证据，不引入第二个并列观点。若标题里出现"且/和/与/以及"，通常说明这页该拆成两页。
- **为什么**：页内多观点会让标题变得笼统、视觉层级瓦解、观众不知该看哪里，论证更难跟随。一页一观点让"标题=观点、正文=证据"的结构成立。
- **反例**：一页同时讲"市场规模"与"候选合作伙伴"两个话题。
- **正例**：拆成两页——P1"目标市场年增 X%，机会规模 $Y"；P2"已识别三家合作候选，合计收入 $Z"。
- **适用场景**：所有内容页。
- **检查勾选（程序化）**：☐ 本页是否只围绕标题一个观点？☐ 标题中是否含"且/和/与/以及"等并列词（若有→考虑拆页）？

### N3 翻页测试：只看标题能否读懂整个论证（Storyline）

- **规则**：把全篇标题按顺序抽出来单读，应能构成一条逻辑连贯、结论递进的故事线（Minto 金字塔：结论先行、层层支撑）。做不到，说明标题或结构需重写。
- **为什么**：这是咨询公司实际的交付质检动作（"flipping through the deck"）。决策者常只翻标题；标题串联读不通，等于整份 Deck 的论证不成立。
- **反例**：标题依次为"市场""产品""团队""财务"，只见领域、不见论点，串不成故事。
- **正例**：标题依次为"目标市场高速增长 → 现有方案无法满足该场景 → 我方方案将效率提升 40% → 投入回收期 18 个月"，逻辑闭环。
- **适用场景**：整套 Deck 的结构审查（可先于逐页排版检查执行）。
- **检查勾选**：☐ 仅读标题是否构成连贯故事线？☐ 是否结论先行、层层支撑？

## 动画与交付（Motion & Delivery）

### M1 重排/优化页的交付形态：独立新文件 + 成品渲染图，不改原文件

- **规则**：对既有文件的"重排/优化单页"任务，默认产出**独立 .pptx（仅含新页，套用原母版）+ 每页成品 PNG 渲染图**，不直接改写用户原文件；用户自行将页拷回或确认后再回写。
- **为什么**：原文件常含用户手动微调，直接覆盖会破坏其工作；独立文件+渲染图让用户先"看见"再决定，回退成本为零。
- **反例**：直接改原 .pptx；或只给 pptx 不给渲染图，用户需自己打开逐页检查。
- **正例**：输出 `xxx_优化版.pptx` + `renders/slideN.png`，同时交付文件和预览。
- **适用场景**：所有"参照/优化/重排某几页"的交付。用户明确要求 in-place 修改时从其要求。
- **检查勾选**：☐ 是否独立成文件、未覆盖原件？☐ 是否附成品渲染图？

### M2 不得创作文案（No Copy Invention）

- **规则**：重排/优化页的输出文字必须 ⊆ 原页文字 ∪ 用户原话；禁止自行撰写新文案（结论带、口号、总结句等）。拟新增文案只能在对话中给出文本请用户确认，确认后方可入页。
- **为什么**：重排任务的边界是"版面"，文案是用户的发言权和业务判断；自创文案哪怕方向对，也必然带着未经确认的业务口径（如"交易在银联"这类表述），正式场合风险不可控。
- **反例**：重排时自加页底结论带"交互在AI · 交易在银联 · 增长在智能体入口闭环完成"——该句不在原页也不在用户话中，用户须手工删掉。
- **正例**：金句按用户原话逐字排版；发现"可以加一句总结"时，在回复中给出候选文案请用户定夺。
- **适用场景**：仅排版重排/优化任务。新建、翻译、换行业或用户已授权改写的任务，可以在授权范围内创作文案，并核实事实。
- **检查勾选**：☐ 输出页文字是否均为原页文字或用户原话？☐ 拟新增文案是否已单独列出待确认？

#### M2 补充：排版优化类任务的文案边界（2026-10 追加）

- **规则**：当任务性质是**排版优化 / 版式重绘**（而非"重写内容 / 换行业改写"）时，**默认不大幅改动原有文案**。原有文字原样保留、只调版面，是这一类任务的第一选择。仅当某处文案**确切违反某条排版规则**（典型：N1 标题写成了主题词而非结论句、N2 一页多观点、超出文本框容量需压缩）时才提出改写，且必须：
  1. **逐条列出「原文 → 建议文案」**，说明触犯的是哪条规则；
  2. 取得用户明确确认后才写入；用户未确认时保留原文、只做版面处理；
  3. 不做与规则无关的"顺手润色"（改语气、改术语、加小标题、加结论带）。
- **为什么**：排版任务的价值是"让已有的内容更好读"，不是"换一套说法"。文案是用户的发言权与业务口径，任何未经确认的改动都会在正式场合产生不可控的口径风险。规则驱动的改写范围可界定、可复核；自由润色则无法界定。
- **反例**：用户只说"优化排版"，执行时把 24 条页标题全部重写、把卡片正文字句重新组织、给每页加一条自拟结论带——即使文笔更好，也超出了任务边界。
- **正例**：版面全量重构，文案逐字不动；仅把"Technology Capability"这类主题词标题按 N1 改写成结论句，并在动手前列出改写清单请用户确认。
- **适用场景**：一切以"排版/版式/视觉"为目标的优化任务；用户说"重写内容/换行业/改口径"时，按该任务授权范围改写，不再套用排版任务的原文子集限制。
- **检查勾选**：☐ 本次改动是否只动了版面、文案是否逐字保留？☐ 若有文案改写，是否每条都能指到具体规则 + 已获用户确认？☐ 是否避免了无规则依据的润色？
