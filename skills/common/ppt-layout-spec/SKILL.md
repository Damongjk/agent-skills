# PPT 设计与验收规范

[规则集](references/ppt-layout-rules.md)是唯一个人规范来源。Codex、WorkBuddy 和 AStudio 共用本入口；不依赖特定客户端、插件或操作系统。

## 执行方式

1. **识别任务边界**：区分只读分析、文案建议、仅排版、新建/改写、仿照定稿。先读完整内容与故事线；用户已明确的范围和授权直接执行，不重复索要确认。
2. **设计前**：读取规则集的“适用与优先级”和“设计前速查”。有既有 PPT 时，检查实际母版、版式、占位符、参考线及有效样式，形成当前稿的固定项、可变项和特殊页约束，再设计正文。
3. **交付前**：结合文件结构、逐页成品和跨页对照检查。适用项记录 PASS / FAIL / MANUAL，不适用项记 N/A；修正授权范围内的问题，明确未验证项。文案建议不自动写入 PPT，只读审查不修改文件。

仿照已批准的白底、蓝青方案型风格时，可按需读取[量化参考配置](references/reference-profile.md)。它是有适用条件的测量示例；不同模板、页面比例、语言或受众应重新校准，不把示例数值当全局硬约束。

## 必须保持的边界

- 用户当前指令及指定定稿优先于通用偏好。保留已批准的母版元素、位置、字号层级与语义断行；正文构图按内容任务选择。
- 仅排版时逐字保留内容、数据、顺序、备注和隐藏状态。需要改文案而尚未获授权时，给出具体建议；新建、翻译及已授权改写无需逐句重新确认。
- 复杂架构、流程、闭环的层级、连接、分组、方向承载语义；视觉优化应保留这些关系。图形直接解释业务问题、机制、证据或价值。
- 简单标签可形文一体；复杂组件可拆分文字和背景，并按编辑用途合理组合。保证文字对齐和安全移动，不强制所有卡片使用一种对象结构。
- 以可编辑 PPT 为主要交付，保留原生图表/表格及数据、媒体和备注。检查渲染默认放在项目外的临时目录。macOS 原生校验按 M1 把副本放进固定文件夹，用系统命令 `open -g -b com.microsoft.Powerpoint` 打开，随后在 PowerPoint 中检查或导出。不自动增加 PDF、全篇总览图或长期备份堆积。

## 自动检查的解释

| 检查信号 | 必须结合的判断 |
| --- | --- |
| 占位符、字体与位置 | 解析母版—版式—页面继承、局部覆盖与组合变换；不能只读当前形状的显式属性 |
| 文本内边距与对齐 | 对齐类文本框通常归零；容器留白也可通过对象偏移建立。比较文字可见边缘、基线或中心，不只比较框顶边 |
| 换行与自适应 | 保留有意分行；固定多行短句可关闭自动换行，连续段落可开启。标称框宽不一定等于自动适配后的可见宽度 |
| 圆角 | 检查同类组件的实际视觉半径；可随形状尺寸使用不同 adj。禁止无条件统一为 0.08；排除药丸、圆形等不同角色 |
| 颜色、字级与密度 | 按信息角色、对照组、背景及放映场景判断；不按原始色值数量、最小字号或空白面积一票否决 |
| 叙事、媒体与编辑能力 | 连线语义、统计口径、截图性质、备注、隐藏状态与媒体关系分别核验；截图通过不代表原生功能已通过 |

具体规则与验收证据见规则集。只有图片时只做视觉判断；未打开 PowerPoint、未播放媒体或未做跨设备检查时，不宣称已完成这些验证。
