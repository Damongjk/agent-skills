## 链接保真

- `text_field_as_array=True` 返回的原始分段才用于保护旧内容。mention 的 token/类型和 link 分开保存，快捷方式 token 不能替代目标 token。
- Text 追加通过 base_materials_plan 保留原分段、换行、显示名与真实链接，按 URL 去重；随后使用保真写入开关和目标字段指纹。当前平台若拒绝数组写入，不自动改成字符串。
- 文件名相同、显示文本相同都不能证明链接相同；既有“文件名”显示不是缺链接证据。读不到真实分段则暂缓该非空字段，其他可独立更新的字段继续执行。
- 新链接来自用户、inspect 或 MCP 返回的真实 URL。快捷方式只在返回真实目标坐标/URL 后使用；无法解析时保留待核实项。
- 普通文档材料使用具体文件链接，不以文件夹替代。产品音视频历史存在集合文件夹 URL 约定，方案音视频历史使用文本集合链接；以当前记录和业务约定为准，不统一覆盖现有单文件链接。
- URL 字段使用 link/text 对象；Text 富文本分段、人员、附件和关联字段不能互套格式。

## 不完整材料

新增记录无材料时留空；更新记录无新材料时不发送字段。空目录不填占位链接。附件遵循当前平台能力，普通 Drive token 不能当 Base 附件上传。

简介须读取正文。目录标题和文件名仅用于定位，不足以推导完整能力、成交案例或商业承诺。
