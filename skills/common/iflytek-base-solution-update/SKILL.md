# 星火国际货架维护

平台操作仅走 ifeishu MCP。先检查本次工具签名，不把历史能力缺口写成永久限制；首次批量操作先 conventions，用户给的新链接先 inspect。

## 入口与范围

从 `~/.cc-switch/local-context/ifeishu-resources.json` 的 `shelf` 读取已验证 Base、表、记录和素材目录映射。入口缺失时先复用本次会话已验证链接，否则请用户提供真实链接。按用户请求保存确认后的入口；业务坐标、基线和进度只留本机，不进入技能 Git 包。

默认更新已映射的产品、方案、服务素材。客户案例以真实内容确认为准，不凭目录名新增。优先记录级目录，不从整个共享空间开始扫；接待管理、国内学习资料等未映射目录不自动纳入。共享目录可对应多条记录，不能将其全部文件一律写入每条记录。

## 增量更新

1. `base_query(app)` 确认当前表；`list_fields=True` 分页读取字段类型。读取已有记录时使用 `text_field_as_array=True`，保留原始分段、真实链接、显示名称和提及 token；旧索引不替代当前读取。
2. 支持 `drive_scan` 时，按映射中的 scan_scope 启动，以完整且同范围的基线比对，保存 scan_id 后分批 resume；失败用 retry_failed。按 next_offset 读取全部变化项。工具缺失时可用 drive(list) 分页遍历并保存本机进度；两者都不可用时才报告能力缺口，不走 CLI/API 直连。
3. 首次、范围变化或用户明确要求时全量建立基线。增量扫描仍读取范围内所有目录清单，不以父目录修改时间跳过子树；仅对新增、变化或待处理文件读取正文。not_observed 只列为待核实，不代表文件失效或应删除。
4. 根据 [字段与素材规则](references/material-rules.md) 和已验证映射生成字段级差异。已有同一真实链接不重复追加；空目录不占位、同名不认作同一文件。映射不明或素材不足时保留现值并登记待核实项。
5. Text 材料追加优先 `base_materials_plan`，审阅其 changes 与 records，再用 `base_write(action=update,preserve_material_links=True)` 提交；空计划不写。保留原富文本分段，禁止用文件名反查出的链接重建整个单元格。不支持富文本写入时保留原值并报告，禁止降级为纯文本覆盖。URL、简介等其他字段按当前类型单独处理，只写明确目标字段。
6. 写前检查目标字段指纹；每批最多 500 条，检查逐项状态。不确定结果先回读，不能重放。用富文本模式核对写后真实链接、原显示名、目标字段和未改数据。按现有日志约定记录实际成功更新，避免重复日志。
7. 扫描结束不等于更新完成。分别保存完整扫描基线、实际写入验证和待处理清单；新基线不能让上次暂缓项消失。细节见 [进度、基线与映射](references/incremental-state.md)。

## 保护边界

- 产品等级、海外适配、部署区域、人员和跨表关联按既有人工约定维护，除非本次明确授权；Lookup 等只读字段不写。
- 简介依据正文归纳，不推断报价数值、负责人或缺失能力。报价字段可链接真实报价文件，不代客户确定价格。
- 不删除任何货架 Drive 文件；本技能不自动清理文件或创建定时任务。
- 更新日志中的通知标志不是外发授权；不额外发消息。
- 权限/读取失败不得当成空目录；部分成功不自动回滚。只对变化或不确定项继续核验，避免重复全表、全目录扫描。
