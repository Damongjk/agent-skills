# MCP 架构与维护约束

来源：原 WorkBuddy ifeishu-mcp-ops、退役 ifeishu-mcp-server 与平台知识；2026-10-27 按会话实际工具定义复核。历史重试次数/版本号仅作线索，以本机代码为准。

Agent → MCP stdio → 服务工具 → 本地兼容层 → 定制适配器 → i讯飞。Agent 只调用 MCP；服务内部实现可以使用当前定制 CLI，不等于允许业务 Agent 直接调用 CLI。新增能力应集中到 MCP，避免每个 Agent 再做一份平台适配。

- stdout 专用于 MCP 协议，日志走 stderr 或受控日志文件。底层适配的 stdout JSON 与 stderr 不合并；错误返回可操作 hint，日志清除凭据和敏感内容。
- 认证集中在设备安全配置。Windows 旧环境中 `LARKSUITE_CLI_USER_OPEN_ID` 名称误导，其值曾实际承载外部认证凭据，不是普通人员 ID；不要打印或复制。Mac 不能照搬注册表兜底。
- 不把官方 npm 版当作当前私有云定制适配器的直接替换。升级前确认私有品牌、外部认证、参数和行为兼容；业务任务不升级依赖。
- 长文本/JSON 使用安全结构化传递，服务内部可用 stdin 避免 Windows 引号与长度问题；后台子进程不弹出可见窗口。
- 服务公共接口与底层端点分开：当前 base_write 公共 records 参数为对象数组；内部 batch_delete 转换成字符串 ID 数组。不能照搬底层格式给公共工具。
- 创建/更新批量端点单批最多 500；检查实际结果，不能仅用返回条数推断每项成功。写入默认不自动重试；读取只对暂态错误有限重试，次数与超时以实现为准。
- 修改服务后校验语法、工具注册、参数契约及错误分支。写操作测试须明确目标并可核对；未知写入结果先查询而非重放。
